# Wuzi Codes Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement task-by-task. The user has explicitly approved this specification and requested implementation; no additional planning gate is required.

**Goal:** Publish a verified, original minimalist blog preserving Wuzi's archive.

**Architecture:** Fresh Hugo 0.169.0 project producing static `dist/`; source-based Markdown, custom templates/CSS and small progressively enhanced JS. GitHub maintains the source; Sites hosts identical tested source/build versions.

**Tech Stack:** Hugo 0.169.0, Node 24 build wrapper, Python standard-library migration assertions, browser JavaScript/CSS.

**Spec:** `docs/superpowers/specs/2026-11-04-wuzi-site-design.md`

## Global Constraints
- Original repositories untouched; new public wuzi/wuzi.dev only.
- Import exact original articles/assets; do not run legacy deploy.sh.
- No Cactus dependency, framework runtime, CMS or hosted storage.
- Lowercase commit subjects; no GitHub/Jira comments or reviews.
- Draft requests never publish; approved blog is intended public.
- Owner performs DNS change; report actual verification boundaries.

## Review Focus
- Taxonomy-index RSS entries are terms, not copies of the article feed.
- Preview URLs must work while canonicals remain wuzi.dev; analytics must remain inactive there.
- Missing paths must be HTTP404, not the homepage or a success-coded error page.
- Draft/future content must not enter indexes, feeds, navigation or public sources.
- Browser storage/clipboard failures must leave reading/navigation usable.
